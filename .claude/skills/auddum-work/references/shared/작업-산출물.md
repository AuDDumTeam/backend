# 작업 산출물

임시 산출물은 gitignore된 `_workspace/<run-id>/` 아래에만 쓴다. 결정과 이유는 sketch, 확정된 것은 정본에 있으므로 여기에는 둘 수 없는 원문만 남긴다. `00_brief`와 `40_delivery`는 쓰지 않는다(작업 지시는 sketch가, 전달 결과는 PR이 맡는다).

| 파일 | 작성자 | 내용 |
|---|---|---|
| `00_diff-r<k>.patch` | 오케스트레이터 | 리뷰 대상 diff(`git diff develop...HEAD`) |
| `00_canon-diff.patch` | 오케스트레이터 | wrap에서 바뀐 정본 변경분(fact-verifier 입력) |
| `20_test-writer_note_q<k>.md` | test-writer | 테스트 작성 결과 |
| `20_test-writer_bug-report_q<k>.md` | test-writer | 코드가 정본과 다르게 동작할 때만 |
| `30_sketch-reviewer_report_r<k>.md` | 오케스트레이터가 최종 응답을 저장 | sketch 검토 원문 |
| `30_domain-reviewer_report_r<k>.md` | 오케스트레이터가 최종 응답을 저장 | 정책·정본 리뷰 원문 |
| `30_code-reviewer_report_r<k>.md` | 오케스트레이터가 최종 응답을 저장 | 설계·품질 리뷰 원문 |
| `30_fact-verifier_report_r<k>.md` | 오케스트레이터가 최종 응답을 저장 | 정본 변경분 검증 원문 |

- `q<k>`는 요청 순번, `r<k>`는 리뷰 라운드. 1부터 세고 같은 이름이 있으면 덮어쓰지 않고 올린다.
- run-id는 브랜치 이름에서 앞의 `feature/`를 떼고 `/`를 `-`로 바꾼 것이다. 예: `feature/129-auddum-work-skill` → `129-auddum-work-skill`, `chore/foo` → `chore-foo`.
- 리뷰어는 읽기 전용이라 파일을 쓰지 못한다. 리포트는 최종 응답으로 받아 오케스트레이터가 **전문 그대로** 저장한다. 요약만 저장하지 않는다. 이유: 재진입과 재리뷰 때 원문이 기준이다.
- 에이전트 호출 프롬프트는 경로만 준다: 입력 파일, 출력 파일, 읽을 docs.

# 정본 갱신 매핑

어떤 변경이 어느 문서를 고치게 하는지의 표다. 정본 위치의 근거는 `docs/index.md`의 "어디서 찾나(정본)"이고, 여기에는 변경 → 문서만 둔다. wrap에서 이 표로 갱신 대상을 찾는다.

| 변경 | 고칠 문서 |
|---|---|
| 사용자 시나리오·정책·운영 시나리오, 기능별 규칙·흐름·예외 응답 | `docs/features/` 해당 페이지(이력 표도) |
| 도메인 행위·규칙, 상태 전이, enum 값 | `docs/domain/도메인-모델.md` |
| 새 용어, 영문 이름 | `docs/domain/용어집.md` |
| 테이블·제약·인덱스 | `docs/ERD.md` |
| 패키지·레이어·서비스·응답 규칙 | `docs/engineering/아키텍처.md` |
| API 공통 규칙, 오류 응답 형식 | `docs/engineering/API-공통-규칙.md` |
| 토큰·쿠키 | `docs/engineering/인증.md` |
| 중복 참여·동시 요청 | `docs/engineering/동시성-중복-방지.md` |
| 코드·테스트 컨벤션 | `docs/engineering/컨벤션.md`, `테스트-전략.md` |
| 이번 이슈에서 확정한 결정·코드 관행 | `docs/engineering/설계-결정.md` |
| 엔드포인트·오류 코드 | 직접 고치지 않는다. 코드를 바꾸고 생성 문서를 갱신한다(`./gradlew build`가 비교) |
| 마일스톤 완료 | `docs/product/로드맵.md` 체크박스와 이슈 번호 |
| 브랜치·커밋·PR 절차 | `docs/howto/개발-워크플로.md` |
| 겪은 함정 | `docs/records/pitfalls.md`(한 번 겪으면 교훈, 두 번 겪으면 규칙으로 올리고 지운다) |

정본을 고치면 sketch의 `features`·`ids`·`decisions`와 기능 페이지 이력 표를 서로 맞춘다. 자동으로 확인하지 않는다.
